# Structured evidence handoff

Return the research as a portable JSON/text bundle for the receiving agent. Research one supplied prospect; company discovery is separate. The receiver can apply private seller knowledge to assess fit, question claims, explore sources and choose its own presentation. No PDF, typography, slide, outreach or report-rendering dependency is part of this skill.

## Output contract

Use the existing schemas in [evidence-schema.md](evidence-schema.md); do not invent a parallel report schema.

| File | Receiver use |
|---|---|
| account.json | Prospect identity, scoped workflows, reported/inferred claims, provisional seller relevance and unknowns. References the seller profile ID/revision/hash. |
| sources.json | Source URLs, publication/upload/event/retrieval dates, review coverage, exact passages, locators, interpretation, verification and limits. |
| research-log.json | Questions, actions, round gains, checkpoints, failed routes, closure reasons and remaining public leads. |
| sources/ | Retained supporting text/captions referenced by sources.json; no raw media. |
| START_HERE.md | Short navigation and limitations note, including jobs reviewed versus discovered, media coverage and how to trace a claim. |
| manifest.json | Exported file hashes and account identity, generated by the exporter. |

Keep source wording separate from interpretation. Preserve source scope, date precision, contradictions and corrections. An assessment is a research hypothesis, not a prefilled receiving-agent verdict; do not require the receiver to accept it. Link claim -> evidence -> source passage and question -> research action/closure using the existing IDs. Keep private seller docs/code, consent receipts and build/runtime files outside the bundle.

## Validate and export

Run from the installed skill directory, replacing RUN and NEW_BUNDLE_DIR with actual paths:

```sh
python3 scripts/validate.py run RUN --final
python3 scripts/bundle.py export --run RUN --output NEW_BUNDLE_DIR
python3 scripts/bundle.py verify --output NEW_BUNDLE_DIR
```

The exporter creates a fresh allowlisted directory and ZIP with SHA-256 manifest and refuses overwrite. Extract the ZIP into a fresh directory and verify that extracted directory too. Review passage interpretation and actual export scope; structural and security-pattern checks do not prove factual accuracy or exhaustive research. Preserve earlier exports.

## Return to the caller

Link the verified bundle/ZIP and START_HERE.md. Lead with a short, account-specific explanation: consequential seller-relevant workflow findings, existing controls or counterevidence, and decisive unknowns. Cite the supporting IDs/links. Offer a few concrete follow-up questions drawn from this account; avoid a generic file-count receipt or a prefilled sales verdict.

The JSON/text evidence is canonical. Continue in the same conversation through [qa.md](qa.md), using original passages, contrary evidence and the research log. Reopening the bundle later uses the same offline Q&A route. Private seller context may refine relevance without changing prospect facts; a PDF or outreach remains a separate task.
